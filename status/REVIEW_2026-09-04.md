# harpelle.github.io review, 2026-09-04

Reviewer: Claude Code (Fable 5.1 review). Read-only; nothing deployed or changed outside `status/`.

## Executive summary

harpelle.com is a plain static site on GitHub Pages (legacy Jekyll build, `main` branch, custom domain, HTTPS enforced) that carries the studio home, the VolleyTally and VolleyTrack product pages with their privacy, terms, help, demo, coach-test, and feedback pages, private client engagement pages under `/clients/`, and one Cloudflare Worker (`workers/volleytrack-feedback`, D1-backed) that receives the VolleyTrack feedback form.
The site is live and healthy in the basics: no open Dependabot alerts, no repo workflows (only GitHub's default CodeQL setup), www redirects to apex, the feedback Worker answers CORS preflight for harpelle.com, and every internal link on the published pages resolves except one.
Main is at PR #6. The Primary Mac checkout is two merges behind main and holds an uncommitted, coherent set of edits dated 2026-08-05: every `info@harpelle.com` contact on the VolleyTrack and VolleyTally pages becomes a per-app `info@` address, and the Worker gains a `send_email` binding pointed at `info@volleytrackapp.com`. They look worth committing, split into a site commit and a Worker commit.
Two things are wrong today: the Swing Time client page links to a `proposal.html` that does not exist (404 live), and internal files (`status/`, `workers/`, `scripts/`, `AGENTS.md`) are published on harpelle.com because Pages publishes the whole repo.
Most important next step: land the contact-email migration from the Primary checkout, then add a `_config.yml` exclude list so internal files stop being served.

## Issues

### P0

None found.

### P1

1. **Broken link on a client-facing page.** `clients/swing-time-83dc2d/index.html` line 76 links to `proposal.html`, which is not in the repo; `https://harpelle.com/clients/swing-time-83dc2d/proposal.html` returns 404. Fix: add the proposal page from `clients/_template/proposal.html` or remove the band until one exists.
2. **Internal files are published.** `status/CURRENT.md`, `status/status.json`, `AGENTS.md`, `workers/volleytrack-feedback/wrangler.toml` and `src/index.js`, and `scripts/create-volleytrack-doc-screens.sh` all return 200 on harpelle.com. Nothing secret is in them (the D1 database id is not a credential), but the status folder describes internal machines and plans. Fix: add `_config.yml` with `exclude: [status, AGENTS.md, README.md, workers, scripts, .codex]`; the legacy Jekyll build already hides `clients/_template` because of the underscore, and this keeps that behavior (do not add `.nojekyll`, which would publish the template).
3. **Uncommitted contact-email migration on the Primary checkout** (`/Users/jasonpaschall/HarpElle/HarpElleSites/HarpElle`, 18 modified files, 36 insertions / 33 deletions). Site pages move support links to `info@volleytrackapp.com`, `info@volleytallyapp.com`, and `info@harpelle.com`; `wrangler.toml` adds `[[send_email]] name = "EMAIL"` and sets `NOTIFY_TO`/`NOTIFY_FROM`. All three domains have Google Workspace MX records; whether the `info@` mailboxes exist and are read is unverified. Fix: confirm each inbox receives mail, then commit the 17 site files as one PR and the Worker change together with its deploy.
4. **Email migration is incomplete even with the local edits.** `info@harpelle.com` appears 59 times in the repo today; the local diff replaces about 33. The rest sit in `volleytrack/coach-test/`, `volleytrack/demos/`, `volleytrack/print/`, and several help pages. Fix: one sweep so `grep -rn 'info@harpelle.com'` returns zero, unless Jason wants the personal address to stay somewhere on purpose.

### P2

5. **Feedback Worker hardening** (`workers/volleytrack-feedback/src/index.js`): no rate limit, no request body size cap before `request.json()`, and the feedback page (`volleytrack/feedback/index.html`) does not say that name and email are stored (D1) or for how long. Fix: cap body at 16 KB, add a Cloudflare rate-limit binding or Turnstile, add one sentence of retention copy under the form.
6. **VolleyTrack launch copy may be stale.** `volleytrack/index.html` says "Release-candidate testing is underway" with Google Play marked "Review"; `volleytrack/coach-test/index.html` says "final stretch before launch." The App Store link `id6758875792` did not return a page title from a plain fetch; store status is unverified. Fix: confirm status and refresh both pages in the same PR.
7. **Two VolleyTrack landing pages.** `volleytrackapp.com` is live with its own landing page and links back only to `harpelle.com/`, not to the help center. `llms.txt` still points VolleyTrack at `harpelle.com/volleytrack/`. Fix: decide the canonical product URL (see questions) and cross-link help from volleytrackapp.com.
8. **Client demo depends on unpkg at runtime.** `clients/swing-time-83dc2d/{demo,pitch}/support.js` load React, ReactDOM, and Babel standalone from unpkg.com in the browser. Works today, but a single CDN outage or a blocked script breaks a sales demo. Fix: when the next client demo is exported, pre-render or self-host the three scripts under `clients/<slug>/vendor/`.
9. **Font loading is inconsistent.** Home and product pages self-host Plus Jakarta Sans and Zilla Slab (`assets/fonts/`); the 15 help, feedback, and coach-test pages load them from fonts.googleapis.com. Fix: point `volleytrack/help/help.css` at the self-hosted files and drop the `<link>` tags.
10. **CodeQL default setup runs on every push, including `[skip ci]` docs commits.** Free on a public repo and about one minute, so cost is negligible; noted so nobody expects `[skip ci]` to suppress it. Fix: none required; disable default setup in repo settings if the noise bothers you.
11. **Dead branch.** `agent/harpelle-pages-studio-containment-20260724` is merged (PR #1). Fix: `git push origin --delete agent/harpelle-pages-studio-containment-20260724`.
12. **Docs drift.** `README.md` is one line. `privacypolicy.md` (VolleyTally, raw Markdown at the site root) is referenced by nothing in the repo; if the store listing points at it, keep it, otherwise redirect readers to `volleytally/privacy.html`. Untracked in the Primary checkout: `assets/PARfectPutt-phone-fast-scoring@2x.png` (unreferenced) and `.codex/config.toml`.
